What your folder URL means
==========================

You sent:

https://fuseintegration.sharepoint.us/sites/Production/Shared%20Documents/Forms/AllItems.aspx?id=%2Fsites%2FProduction%2FShared%20Documents%2Fcapacity%2Dmain&viewid=0143a1d4%2Df4ee%2D457f%2Da3f9%2D0338f5a5bdef

Decoded, that folder is:

  /sites/Production/Shared Documents/capacity-main

So the file address is:

  https://fuseintegration.sharepoint.us/sites/Production/Shared%20Documents/capacity-main/index.aspx

That is the same address that already said file not found.


WHY
---
The file IS uploaded. Copy-link gave download.aspx, which proves SharePoint has the file.

SharePoint on this site will not RUN .aspx or .html as a webpage.
It will only download them. Embed then shows "file not found" or a blank box.

This is an IT lock (custom script / government tenant).
It is not a bad folder name and not a bad iframe.


IFRAME (only works if IT unlocks pages)
---------------------------------------

<iframe src="https://fuseintegration.sharepoint.us/sites/Production/Shared%20Documents/capacity-main/index.aspx" width="100%" height="1000" style="border:0;"></iframe>


WHAT TO DO NEXT
---------------
Pick one:

1. Ask IT / a site admin
   "Please allow custom script on the Production site so we can open
    Site Assets or Documents HTML/ASPX pages in the browser."
   After they do that, the iframe above can work.
   On sharepoint.us this is often not allowed.

2. Host the app somewhere that serves a real webpage
   Then embed THAT https address on the SharePoint page.
   Examples: internal web server, Azure Static Web Apps (Gov if required).
   Public GitHub Pages will show the app, but shop data would not stay
   in your SharePoint tenant. Ask IT before doing that.

3. Stop using Embed
   Keep the files in Documents as a backup.
   People cannot run the tracker from SharePoint until 1 or 2 happens.


DO NOT KEEP TRYING OTHER FOLDER NAMES
-------------------------------------
The path is already correct. More iframe guesses will fail the same way.
