IT: App registration so the HTML Capacity Tracker can use SharePoint lists
==========================================================================

Site (data stays here):
  https://fuseintegration.sharepoint.us/sites/Production

The shop will use a local HTML app (CapacityTracker.html) as the
screen. All data is read and written to four lists on Production
through Microsoft Graph, as the signed-in user.


Create the app (Azure Government portal)
----------------------------------------
1. Open https://portal.azure.us
2. Azure Active Directory → App registrations → New registration
3. Name: Capacity Tracker
4. Supported account types: this directory only
5. Redirect URI: leave blank
6. Register

Then:
7. Authentication → Allow public client flows = Yes → Save
8. API permissions → Add a permission → Microsoft Graph → Delegated:
     Sites.ReadWrite.All
     User.Read
   Grant admin consent
9. Copy Application (client) ID
10. Copy Directory (tenant) ID

Give those two IDs to the shop. They paste them in the HTML app
Settings, then Sign in with their work account.


Lists on Production
-------------------
Create (or allow the shop to create) these lists:

  CT Work Centers
  CT People
  CT Work Orders
  CT Time Off

Script: sharepoint/New-CapacityLists.ps1
Users need Contribute on those lists.


What this is not
----------------
Not GitHub Pages. Not JSONBin. Data does not leave the tenant
except to Microsoft Graph in this GCC High cloud.
